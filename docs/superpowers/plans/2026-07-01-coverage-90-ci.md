# Coverage → 90% + CI Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) tracking. This is plan 2 of 4 for release 1.3.0, executed inline on branch `release/1.3.0-perf`.

**Goal:** Raise measured line coverage of `lib/` from **67.7%** to **≥90%** by unit-testing pure Model-Update-View logic, and mark the genuinely-untestable ~5% with `// coverage:ignore` so the number is honest, then enforce it in CI.

**Architecture:** Additive — new `*_test.dart` files driving existing pure `update()`/`view()`/helpers through their message and key paths. No `lib/` behavior changes except `// coverage:ignore-*` comments on TTY/OS/subprocess/platform code. A Makefile `coverage` target + a CI step enforce the floor.

**Tech Stack:** `package:test`, `package:coverage` (`format_coverage`), GitHub Actions.

**Baseline (measured on this branch):** overall 67.7% (2031/3002). Biggest gaps: `prompts.dart` 0% (0/112), `text_input.dart` 1% (1/90), `viewport.dart` 52%, `file_picker.dart` 53%, `program.dart` 51% (mostly untestable), `renderer.dart` 57%, `text_area.dart` 59%, `table.dart` 60%, `timer.dart`/`stopwatch.dart` ~60%, `key_buffer_parser.dart` 62%, `msg.dart` 63%, `cmd.dart` 72%, `input_decoder.dart` 77%, `list.dart` 80%. New Windows-only `windows_terminal.dart` 21% → ignore.
